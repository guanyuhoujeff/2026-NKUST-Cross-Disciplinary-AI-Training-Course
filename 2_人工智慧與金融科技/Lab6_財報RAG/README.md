# 模組 6 財報 RAG：爬蟲抓真財報 → 加工 → 附引用問答、查無拒答

課程 1 Lab3 做過「最小 RAG」，今天升級成**對真實財報問答**：用爬蟲（Lab1 那招）抓台積電（2330）的財報網頁 → **加工成乾淨記錄** → RAG 附【資料n】出處回答、查不到就拒答不瞎掰。核心是「引用溯源 + 兩道防線拒答 + 數字雙保險」。

## 為什麼用「爬蟲抓網頁」而不是「解析 PDF」？

真財報 PDF（如證交所年報）拿去 RAG 會踩三個坑（實測過台積電官方財報 PDF）：**① 有些頁抽出來是空的**（封面、簽章、圖片頁）；**② 表格變數字湯**（數字有抽到但行列對齊全毀，LLM 對不上哪個數字是哪一季）；**③ 檢索門檻在上百頁時會崩**。改用「爬蟲抓結構化網頁 + 加工成乾淨記錄」就全繞開——這也是為什麼今天**加工那一步才是重點**。

## 環境（跟課程 1 Lab3 混合式一致）

- **embedding 走本地 `bge-m3`**（不帶 key、不耗雲端額度；1.2GB，課前先 `ollama pull bge-m3`）。
- **生成走 Ollama Cloud `gemma4:cloud`**（要 `OLLAMA_API_KEY`；notebook 第 0 步那格直接把 key 貼進引號）。
- **今天新套件是 `requests`**（爬蟲），其餘課程 1 都裝過。
- ⚠️ 本模組生成**不加 `format="json"`**——今天要「自由文字 + 【資料n】標記」，不是 JSON。
- ⚠️ 資料來源（富邦 djhtm）是 **big5 編碼**，抓下來要 `.decode("big5")`。

## 內容

- **A** 爬蟲抓台積電財報頁（綜合損益表 + 財務比率表）→ 先看原始表格多亂
- **B**（重點）加工：HTML 表格 → 乾淨記錄（期別正規化）→ 每筆一個檢索單位建 FAISS → 帶分數檢索
- **C**（課程重點）① `build_context` + prompt 鐵則附【資料n】→ ② `trace_citations` 溯源回表名·期別 → ③ 兩道防線拒答 → ④ `verify_cited_numbers` 數字雙保險
- **D** 收尾：流程圖 + 為什麼用爬蟲不用 PDF + 金融三鐵則

## 出事了怎麼辦（Backup）

| 狀況 | 怎麼辦 |
|---|---|
| `401` / key 沒設 | 第 0 步那格把 `OLLAMA_API_KEY` 引號中間換成老師給的 key，重跑該格 |
| `model not found` | 漏了 `:cloud` 後綴；`gemma4:cloud` 要完整 |
| **爬蟲被擋 / 斷網 / 抓到的表是空的** | 跑最後一格 Backup①：改讀 `data/` 內老師預存的 HTML（把兩行的 `#` 拿掉） |
| 抓到中文亂碼 | 忘了 `.decode("big5")`——富邦這頁是 big5 不是 utf-8 |
| 雲端額度用完 | 建庫、檢索、加工全在本地不受影響；只有 C 段生成打雲端。可降級本地 `ChatOllama(model="llama3.2:3b")` |
| `faiss-cpu` 裝不起來（多見於 Windows） | 改 `chromadb`：`pip install langchain-chroma` → `from langchain_chroma import Chroma`（⚠️ 分數定義不同，門檻要另校） |
| 「我的答案跟同學不一樣」 | 正常——LLM 非決定性。用 `trace_citations`/`verify_cited_numbers` 自動驗根，不靠肉眼比對 |
| 全部斷線 | 跑最後一格 Backup②「最小可跑核心」（純 Python，不需網路/faiss/Ollama） |
